# Migrating from smalldi 0.3 to 0.4

This guide covers the step from 0.3.0 to 0.4.0. The first line of every snippet names the version it runs on; a
snippet that is not runnable on its own is labelled `fragment` there. Coming from 0.2? Use
[0.2 → 0.4](0.2-to-0.4.md) instead.

## Summary

| Change | Breaking | Action required |
|--------|----------|-----------------|
| `@Injector.inject` on an `async def` returns a coroutine function and resolves `Provide[T]` when the coroutine starts running | no | Review coroutine functions whose dependencies are expected before the coroutine is awaited |
| `@Injector.override(Target)` raises `SingletonFrozenError` when the overriding class was requested and has no instance (its constructor is running or failed) | no | Declare overrides before the first request of either class |
| An instance request and the freezing of what it looks up are one step under the injector's lock: an override racing a request is refused instead of succeeding after it | no | None; a racing override fails with `SingletonFrozenError` |
| `Injector.singletons_available` stays deprecated | no | Same as in 0.3: replace reads, see [0.2 → 0.3](0.2-to-0.3.md#injectorsingletons_available-is-a-deprecated-read-only-snapshot) |
| Injection contexts, `ContextAwareThread`, `Injector.get_context`, `Injector.foreign_context` | no | Optional, see [New features you can adopt](#new-features-you-can-adopt) |
| `Injector._singletons_available` and `Injector._interface_resolver` are gone | private | Replace test fixtures that touched them with `Injector.context(...)`, see [Private internals](#private-internals) |

## Breaking changes

None. Every public name of 0.3.0 exists in 0.4.0 with the same signature and the same exceptions, and the only
dependency is still the standard library.

## Behaviour changes without API changes

### `@Injector.inject` on an `async def` resolves `Provide[T]` when the coroutine starts

**What changed**: In 0.3.0 the wrapper of a coroutine function is a plain function: calling it resolves every
`Provide[T]` immediately and returns the coroutine, so `inspect.iscoroutinefunction` is `False` for the wrapper
and the dependencies are built before the coroutine is awaited. In 0.4.0 the wrapper is a coroutine function:
`inspect.iscoroutinefunction` is `True`, and the dependencies are resolved when the coroutine starts running, in
the injection context current at that moment, so an override or context entered between the call and the `await`
is honoured.

**How to find affected code**: `git grep -nE -A1 '@Injector\.inject' | grep -E 'async def'` lists the injected
coroutine functions. Affected are callers that create the coroutine, change the registry (an override, or in 0.4.0
a context) and await it afterwards, and code that checks `inspect.iscoroutinefunction` on the wrapper.

**Before** (0.3.0):

```python
# smalldi 0.3.0
import asyncio
import inspect

from smalldi import Injector, Provide

naps = []


@Injector.singleton
class NapSpot:
    def __init__(self):
        naps.append("NapSpot ready")


@Injector.inject
async def nap(spot: Provide[NapSpot]) -> str:
    return f"Pusheen naps on {type(spot).__name__}"


print(inspect.iscoroutinefunction(nap))  # False
pending = nap()
print(naps)                              # ['NapSpot ready']: resolved by the call
print(asyncio.run(pending))
```

**After** (0.4.0):

```python
# smalldi 0.4.0
import asyncio
import inspect

from smalldi import Injector, Provide

naps = []


@Injector.singleton
class NapSpot:
    def __init__(self):
        naps.append("NapSpot ready")


@Injector.inject
async def nap(spot: Provide[NapSpot]) -> str:
    return f"Pusheen naps on {type(spot).__name__}"


print(inspect.iscoroutinefunction(nap))  # True
pending = nap()
print(naps)                              # []: nothing resolved yet
print(asyncio.run(pending))
print(naps)                              # ['NapSpot ready']: resolved when the coroutine started
```

**How to verify**: Call an injected coroutine function without awaiting it and confirm that no singleton was
constructed; await it and confirm the dependency was built. `inspect.iscoroutinefunction(wrapper)` is `True`.

### Override refusals: an overriding class without an instance, and a racing request

**What changed**: In 0.3.0 `@Injector.override(Target)` succeeds while the overriding class is frozen without an
instance, because its constructor is running in another thread or failed, and the constructor runs a second time
through `Target`. In 0.4.0 that override raises `SingletonFrozenError` and binds nothing. An overriding class that
is frozen with an instance shares it with the target in both versions. In 0.4.0 the lookup and the freeze of
`Injector.get_instance` are also one step under the injector's lock, so an override that races a request for its
target or for the overriding class is refused with `SingletonFrozenError`, and no constructor runs in a
`LazySingleton` the override discarded. See [docs/concurrency.md: Override refusals](../concurrency.md#override-refusals).

**How to find affected code**: `Injector\.override\(` lists every override; `SingletonFrozenError` lists the
code that handles the refusal. Affected are overrides declared after a request for the overriding class, in
particular after a failed construction retried through the override, and overrides declared concurrently with
the first injection of their target.

**Before** (0.3.0):

```python
# smalldi 0.3.0
from smalldi import Injector, SingletonFrozenError

attempts = []


@Injector.singleton
class Pusheen:
    pass


@Injector.singleton
class Stormy(Pusheen):
    def __init__(self):
        attempts.append(1)
        if len(attempts) == 1:
            raise ValueError("Stormy is still asleep")


try:
    Injector.get_instance(Stormy)
except ValueError as error:
    print("first request failed:", error)

Injector.override(Pusheen)(Stormy)  # accepted: the constructor runs again through Pusheen
print(type(Injector.get_instance(Pusheen)).__name__, len(attempts))  # Stormy 2
```

**After** (0.4.0):

```python
# smalldi 0.4.0
from smalldi import Injector, SingletonFrozenError

attempts = []


@Injector.singleton
class Pusheen:
    pass


@Injector.override(Pusheen)  # declared before any request for Pusheen or Stormy
@Injector.singleton
class Stormy(Pusheen):
    def __init__(self):
        attempts.append(1)
        if len(attempts) == 1:
            raise ValueError("Stormy is still asleep")


try:
    Injector.get_instance(Pusheen)
except ValueError as error:
    print("first request failed:", error)

print(type(Injector.get_instance(Pusheen)).__name__, len(attempts))  # Stormy 2: retried through the same binding

try:
    Injector.override(Pusheen)(Stormy)
except SingletonFrozenError as error:
    print(type(error).__name__, error)  # a frozen target accepts no override
```

**How to verify**: Request the overriding class, let its constructor fail, then declare the override: 0.4.0 raises
`SingletonFrozenError`. Overrides declared before the first request of either class, as above, behave the same in
both versions.

## New features you can adopt

* Injection contexts: `with Injector.context(kind):` runs a block in a child context derived from the current one,
  so registrations, overrides and instances made inside are scoped to it; the five kinds are the members of
  `smalldi.context.InjectionSubcontextType`. `Injector.context()` is the replacement for registry-clearing test
  fixtures. See [README: Contexts](../../README.md#contexts) and [docs/contexts.md](../contexts.md).
* `Injector.get_context()` returns the current context and `Injector.foreign_context(ctx)` pushes a given one.
* `smalldi.thread.ContextAwareThread`, a `threading.Thread` that runs in its creator's current context; a plain
  thread or an `asyncio.Task` starts in the root context.
  See [docs/contexts.md: Context trees](../contexts.md#context-trees).
* A thread or Task that finishes with contexts still open has them removed with a `ResourceWarning`.
* [docs/architecture.md](../architecture.md) and [docs/concurrency.md](../concurrency.md) describe the objects behind
  the registry and the locking model.

## Private internals

The 0.3.0 class attributes `Injector._singletons_available` (a `dict` of `LazySingleton` objects) and
`Injector._interface_resolver` do not exist in 0.4.0: the registries belong to the current `InjectionContext`.
A test fixture that copied, cleared and restored them fails with `AttributeError`. Use a context instead:

**Before** (0.3.0):

```python
# fragment: a pytest fixture reaching into 0.3.0 internals
@pytest.fixture
def empty_snack_bowl():
    saved = Injector._singletons_available.copy()
    Injector._singletons_available.clear()
    yield
    Injector._singletons_available.clear()
    Injector._singletons_available.update(saved)
```

**After** (0.4.0):

```python
# smalldi 0.4.0
from smalldi import Injector, Provide
from smalldi.context import InjectionSubcontextType


@Injector.singleton
class CookieJar:
    cookies = 3


@Injector.inject
def count_cookies(jar: Provide[CookieJar]) -> int:
    return jar.cookies


with Injector.context(InjectionSubcontextType.RESET):  # same registrations, fresh unfrozen singletons
    @Injector.override(CookieJar)
    @Injector.singleton
    class EmptyCookieJar(CookieJar):
        cookies = 0

    print(count_cookies())  # 0, inside the block

print(count_cookies())      # 3, outside: the override is gone with the context
```

`InjectionSubcontextType.EMPTY` gives a block with nothing registered, for tests that register everything
themselves.

## Checklist

- [ ] Search for `@Injector\.inject` followed by `async def`; check callers that change the registry between creating the coroutine and awaiting it, and code that inspects the wrapper with `inspect.iscoroutinefunction`.
- [ ] Search for `Injector\.override\(`; declare every override before the first request of its target and of the overriding class, and handle `SingletonFrozenError` where an override may race a request.
- [ ] Search for `_singletons_available` and `_interface_resolver`; replace fixtures that touched them with `with Injector.context(...)` blocks.
- [ ] Run the test suite with `python -W error::DeprecationWarning -W error::ResourceWarning -m pytest`: remaining reads of `Injector.singletons_available` and contexts left open fail the test that performs them.
